# A730 v2: сборка на базе рабочего Gen8 V39

## Что нашлось в рабочем драйвере (Turnip Gen8 V39-patched, StevenMXZ)
- Mesa **27.0.0-devel, коммит 2648b2059f**, Vulkan 1.4.367
- собран **NDK r29**, API 34; файл и SONAME — `libvulkan_freedreno.so`; `minApi` 28

## Чем старый скрипт отличался (возможные причины вылетов)
- брался `main` на момент сборки (свежий, не проверенный на Android/kgsl), а не коммит из рабочего драйвера
- NDK r27c / API 31 вместо r29 / 34
- файл в архиве назывался `vulkan.adreno.so`, а SONAME внутри оставался `libvulkan_freedreno.so`
Какая из причин главная — по этим данным не доказать; поэтому ниже контрольная сборка.

## Что изменено
- `MESA_REF` по умолчанию `2648b2059f` (можно указывать хэш, ветку или тег)
- NDK r29 / API 34 по умолчанию; чужой NDK из окружения берётся, только если совпадает мажорная версия
- имя библиотеки и `libraryName` = `libvulkan_freedreno.so`; в логе проверяется SONAME
- `TU_DEFAULT_DEBUG=nolrz,noubwc` вшивает флаги TU_DEBUG в драйвер (для проверки мерцания без adb)
- `NO_PATCHES=1` — сборка без патчей; `VARIANT` — метка в имени zip
- workflow собирает 4 варианта за один запуск (отдельные артефакты)

## Как пользоваться
1. Распакуйте архив в корень репозитория `DPuncher/A730Aa` (заменит скрипт и workflow, `patches/` остаётся), commit + push.
2. Actions → Build Turnip A730 → Run workflow (значения по умолчанию подходят).
3. Скачайте артефакты и проверяйте **по порядку**:
   - `base` — должен запускаться так же, как V39. Если вылетает — проблема в сборке/упаковке, дальше не идём; пришлите лог.
   - `kgsl` — base + ваши патчи (какие легли, видно в логе шага Build driver).
   - `nolrz`, `noubwc` — тот же base с флагом; смотрите, пропало ли мерцание в Double Exposure на быстром режиме и как FPS.
4. Пришлите, какой вариант что дал.

## Что не проверено
- Mesa здесь не компилировалась (нет NDK и сети): скрипт проверен `bash -n`, вставка флагов — на тестовых файлах, g++ принимает вставляемую строку. Первая реальная проверка — ваш запуск Actions.
- Что именно «пропатчено» в V39, по бинарнику не определить; патчи V39 в вашу сборку не переносились.
- Нет гарантии, что `nolrz`/`noubwc` уберут мерцание: часть мерцаний на быстром режиме — синхронизация памяти в самом Eden. Для производительности пока ничего нового не добавлено: сначала нужна рабочая база.
